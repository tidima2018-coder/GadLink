# GadLink: установка и проверка Realtime

Изменения фронтенда требуют SQL ниже. Автоматического доступа к рабочей БД из этой среды нет: миграции здесь не запускались, фактические публикация, политики и настройки проекта не проверены.

## Порядок SQL Editor

На существующей базе должны быть установлены текущие схемы авторизации, друзей, личных чатов, сообществ, звонков, Push и Reels. Не пересоздавайте базу. Если соответствующие миграции уже выполнены, повторно запускать их не требуется.

1. Существующие зависимости: `auth_setup.sql`, `private_messages.sql`, `community_setup.sql`, `voice_calls.sql`, `reels.sql`, `push_and_sync.sql` — если ещё не установлены, с учётом их собственных зависимостей.
2. Существующие исправления: `friendships_realtime.sql`, `chat_sync.sql`, `profile_avatars.sql`, `public_profile_details_rpc.sql`, `voice_inbox_realtime_fix.sql`.
3. **Новый `user_activity_realtime.sql`.** Таблица активности отдельно от профилей, RPC, приватные Presence-политики. Прямые изменения активности клиентом запрещены; RPC использует время сервера. При скрытии статуса сохранённая дата очищается.
4. **Новый `app_realtime_reliability.sql`.** Политика чтения приватных каналов изменений БД, проверка RLS, добавление таблиц в публикацию, уникальные просмотры Reels. Вся миграция откатывается, если обязательная таблица отсутствует или RLS выключен. Исправьте указанную зависимость и запустите файл снова. Миграция не отключает RLS и не расширяет чтение строк прикладных таблиц.
5. **Новый `app_realtime_diagnostics.sql`** — только диагностика. Для каждой ожидаемой таблицы проверьте `table_exists`, `rls_enabled`, `published`, `authenticated_can_select` и наличие SELECT-политики. Отдельно выполните существующий `voice_realtime_diagnostics.sql`.

Новые миграции идемпотентны. Для звонков обязательна существующая миграция `voice_inbox_realtime_fix.sql`: новое исправление не заменяет её политики.

В Supabase Realtime должен быть включён сервис. Все прикладные каналы изменений БД теперь используют `private: true`, также приватными остаются Presence и сигналинг. Сверьте настройки лимитов подключений/каналов и ошибки join в браузере. Не добавляйте универсальные разрешения на запись в `realtime.messages`.

## Поведение

- Presence наблюдает пользователей, чьи аватары находятся в открытых разделах; для каждого пользователя один приватный канал. Только владелец может публиковать в свой канал. У каждого устройства отдельный ключ, онлайн сохраняется до ухода последнего устройства.
- Закрытие страницы отправляет best-effort `untrack`; при аварийном закрытии или потере сети уход определяется сервером после таймаута соединения. Мгновенное определение аварийного отключения не гарантируется. Последняя активность сохраняется примерно раз в минуту, поэтому дата после аварийного закрытия приблизительная.
- Отключение видимости обнуляет дату в БД; изменение получают остальные открытые устройства владельца и прекращают Presence. У скрытого пользователя показывается «Не в сети». Статус не хранится в публичных полях `profiles`.
- SDK Supabase восстанавливает WebSocket-подписки. При `SUBSCRIBED` представления сверяются с БД; дополнительно есть сверка при возвращении, восстановлении сети и раз в 90 секунд на активной вкладке. Запросы возобновления объединяются с интервалом не менее 5 секунд.
- Открытая история сверяет последние 100 сообщений (существующий размер окна), включая изменения и удаления. Старую историю за пределами окна приложение по-прежнему не подгружает.
- Просмотры Reels считаются один раз на аккаунт и публикацию. Таблица зрителей недоступна клиенту; другим пользователям передаётся агрегат `view_count` через существующую `reel_posts`.
- Выход очищает Presence, его обработчики и таймеры, резервную синхронизацию и существующие каналы приложения, включая обычную ленту.
- Закрытый браузер/PWA не держит WebSocket. Уведомления используют существующие Web Push, Service Worker и Edge Function; для их проверки нужна настроенная отправка и поддержка браузера.

## Что проверено локально

`node --test tests/realtime.test.mjs`: форматирование даты; несколько устройств; скрытие статуса, в том числе с другого устройства; повторная подписка без дублирования канала; очистка таймеров/обработчиков при выходе. Тесты используют имитацию Supabase, а не рабочую БД.

Также выполнены `node --check` для JavaScript проекта и `git diff --check`. Реальных браузерных тестов с двумя аккаунтами и выполнения SQL в Supabase здесь не было.

## Проверка двумя аккаунтами после установки

Откройте A и B в разных профилях браузера. Для каждой операции проверьте обе стороны, не обновляя страницу:

1. Вход A: B видит «В сети» и точку в друзьях, переписках, шапке личного чата и профиле A.
2. Закрытие A: после обнаружения отключения B видит последнее посещение. Проверьте переходы «недавно», минуты, сегодня и вчера.
3. A открыт на двух устройствах: закрытие одного не снимает онлайн. Закрытие обоих снимает.
4. A скрывает статус: B теряет онлайн и дату; второе устройство A прекращает публикацию. Переподключение не возвращает скрытый статус. Включение восстанавливает его.
5. Заявка A → B: входящий счётчик и заявка появляются сразу; принятие, отказ и удаление отражаются у обеих сторон.
6. Сообщение, редактирование и удаление: история, превью, порядок переписок и счётчики меняются у B. Проверить также чтение на другом устройстве B.
7. Имя, фото, «О себе»: обновляются в открытом профиле и списках B; повторить изменение во время отключённой сети B и затем восстановить сеть.
8. Звонок: входящий, принятие, отказ и завершение; проверить WebRTC/TURN и Push с закрытой PWA отдельно.
9. Reels: публикация, удаление, лайк/снятие, комментарий/удаление, просмотр; второй просмотр тем же аккаунтом не увеличивает счётчик. Вернуться в ленту после фонового режима.
10. Отключить сеть B; изменить данные A; восстановить сеть B и убедиться, что все разделы догнали БД. Проверить DevTools: нет повторяющихся каналов и бесконечных запросов.
11. Выйти из аккаунта: каналы удалены, Presence и резервные таймеры остановлены, новые события прошлого аккаунта не меняют интерфейс.

Официальные особенности используемого API: [Presence](https://supabase.com/docs/guides/realtime/presence), [авторизация приватных каналов](https://supabase.com/docs/guides/realtime/authorization), [Postgres Changes и DELETE](https://supabase.com/docs/guides/realtime/postgres-changes).
